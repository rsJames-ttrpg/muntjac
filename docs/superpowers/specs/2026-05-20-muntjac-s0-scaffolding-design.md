# S0 — Scaffolding & Config Spec

**Status:** draft v1 (2026-05-20)
**Companion to:** `2026-05-20-muntjac-design.md` (full design), `2026-05-20-muntjac-roadmap.md` (roadmap)
**Stage:** S0 (first phase-1 stage)

---

## 1. Scope

Stand up the Rust crate, CLI dispatcher, `muntjac.toml` parser, error machinery, and CI so all subsequent stages can plug into a working tool harness. No business logic — no lockfile parsing, no BUCK emission. The deliverable is "the tool runs, validates config, and is ready to be extended."

Out of scope (deferred to later stages): uv.lock parsing (S1), wheel selection (S2), BUCK emission (S3), sdist handling (S5), fixups (S6/S7).

---

## 2. CLI surface (S0 slice)

```
muntjac init [--force] [PATH]      # write starter muntjac.toml + skeleton
muntjac config check [-C PATH]     # validate muntjac.toml in isolation
muntjac debug                      # subcommand group; no children at S0
muntjac --help                     # lists all phase-1 verbs (S1-S8 ones marked UNIMPLEMENTED)
muntjac --version                  # prints version + git sha (CARGO_PKG_VERSION + build-time env)
```

Phase-1 verbs registered but stubbed:

```
muntjac vendor       # UNIMPLEMENTED (S5/S9)
muntjac buckify      # UNIMPLEMENTED (S3+)
muntjac audit        # UNIMPLEMENTED (S10)
muntjac fixups …     # UNIMPLEMENTED (S6/S7)
muntjac unused       # UNIMPLEMENTED (S10)
```

Each stubbed command prints `error: muntjac <verb> is not implemented yet (planned for S<n>); see docs/superpowers/specs/` and exits 2. This lets `muntjac --help` reflect the full surface from day one and gives users orientation.

Global flags (registered in S0, honored where meaningful):

```
-C <path>            # cd into a muntjac project before running
-v, -vv              # log verbosity
--no-network         # forbid any network calls (no-op until S7)
--frozen             # forbid running `uv lock` (no-op until S1/S5)
--tree <name>        # operate on one tree in multi-tree configs (no-op until S11)
```

## 3. `muntjac init` behavior

### Detection algorithm

1. Walk from CWD upward, looking for a `pyproject.toml` whose root table has either `[project]` or `[tool.uv]`. Stop at the first match or at filesystem root. Call this `manifest_path`.
2. If `manifest_path` is found, look for `uv.lock` in the same dir. If present, note `has_lock = true`.
3. Determine target Python versions:
   - If `pyproject.toml`'s `[project].requires-python` is a recognizable range (`>=3.11`, `>=3.10,<3.13`, etc.), expand to the discrete Python versions ≥3.11 inside the range. Cap at the latest known stable (3.13 at time of writing).
   - Otherwise default to `["3.12"]`.

### Files written

In the directory where `muntjac init` is invoked (CWD, unless `[PATH]` given):

```
muntjac.toml               # starter config (see template below)
third-party/python/
├── BUCK                   # placeholder: `# Generated by muntjac. Run: muntjac buckify`
├── .gitignore             # contains `vendor/` and a marker comment
└── fixups/                # empty dir with a .gitkeep
```

If the user's `.gitignore` doesn't already cover `~/.cache/muntjac` patterns, no edits are made — muntjac's cache is in `~/.cache`, outside the repo, so nothing to ignore.

### Starter `muntjac.toml` (detected case)

```toml
# Generated by `muntjac init`. Edit freely.
# See docs/superpowers/specs/2026-05-20-muntjac-design.md for full schema.

manifest_path   = "../pyproject.toml"       # detected at init time
third_party_dir = "."                       # this directory
python_versions = ["3.11", "3.12"]          # derived from requires-python

[platforms]
linux-x86_64-gnu  = { target = "x86_64-unknown-linux-gnu",  manylinux = "2_17" }
linux-aarch64-gnu = { target = "aarch64-unknown-linux-gnu", manylinux = "2_17" }
linux-x86_64-musl = { target = "x86_64-unknown-linux-musl", musllinux = "1_2" }
macos-x86_64      = { target = "x86_64-apple-darwin",       macos_min = "11.0" }
macos-arm64       = { target = "aarch64-apple-darwin",      macos_min = "11.0" }

[fixups]
# Community fixup registry. Leave as "none" until a v0.1.0+ release exists.
registry              = "none"
allow_local_overrides = true

[buck]
file_name = "BUCK"
vendor    = false
```

### Starter `muntjac.toml` (undetected case)

Same as above, but `manifest_path = "TODO: path to your pyproject.toml"` and `python_versions = ["3.12"]`, with a banner comment:

```toml
# TODO: muntjac init could not auto-detect a uv project.
# Edit `manifest_path` to point at your pyproject.toml, then run `muntjac config check`.
```

### Overwrite handling

If `muntjac.toml` exists in target dir: refuse with `error: muntjac.toml already exists; pass --force to overwrite`, exit 2.

If `third-party/python/` exists but is non-empty: warn, do not overwrite anything inside it, but still write the top-level `muntjac.toml`. The user can clean up manually.

`--force` bypasses both checks.

## 4. `muntjac config check` behavior

Reads `muntjac.toml` (from `-C <path>` or CWD), validates without performing any side effects:

1. TOML parses successfully. Errors include line/column.
2. All required top-level keys present (`manifest_path` xor `[tree.*]`, `[platforms]`).
3. `manifest_path` resolves to an existing file. If absent, error names the resolved absolute path.
4. `third_party_dir` exists or can be created (write-test: create a temp file, remove it).
5. `python_versions` entries are valid `MAJOR.MINOR` strings.
6. Each `[platforms.<name>]` entry has a valid `target` triple (matches a known set: `{linux,macos}-{x86_64,aarch64}-{gnu,musl,(none)}`).
7. `[fixups].registry` is one of: `"none"`, `"file://<path>"`, or matches `^github\.com/[^/]+/[^/]+$`.

Exit non-zero on any failure. On success, print `muntjac.toml ok: <N> platforms, <M> python versions, <tree count> tree(s)`.

Output format: human-friendly by default. `--format json` for CI consumption (returns `{ok: bool, errors: [...], warnings: [...]}`).

## 5. `muntjac.toml` parsing

Implemented via `serde` + `toml`. Two top-level shapes (mutually exclusive):

**Single-tree (default):**
```toml
manifest_path   = "..."
third_party_dir = "..."
python_versions = ["..."]
[platforms]
[fixups]
[buck]
```

**Multi-tree (S11 — schema parses now even if `--tree` is unimplemented):**
```toml
[platforms]
[fixups]
[buck]
[tree.<name>]
manifest_path   = "..."
third_party_dir = "..."
python_versions = ["..."]
```

The parser:

- Accepts either shape; rejects mixed (top-level `manifest_path` + any `[tree.*]`).
- Validates platform target-triple shape but does NOT verify the triple is supported by the host rustc — that's S2's concern.
- Returns a normalized `Config` struct that callers manipulate. Single-tree is internally represented as a `Config { trees: [Tree { name: "default", … }] }` so downstream code has one code path.

Types:

```rust
pub struct Config {
    pub trees: Vec<Tree>,
    pub platforms: BTreeMap<String, Platform>,
    pub fixups: FixupsConfig,
    pub buck: BuckConfig,
}

pub struct Tree {
    pub name: String,                       // "default" for single-tree
    pub manifest_path: PathBuf,
    pub third_party_dir: PathBuf,
    pub python_versions: Vec<PythonVersion>,
}

pub struct Platform {
    pub target: String,                     // rustc target triple
    pub manylinux: Option<String>,          // "2_17", "2_28", …
    pub musllinux: Option<String>,          // "1_1", "1_2", …
    pub macos_min: Option<String>,          // "11.0", "12.0", …
}

pub struct FixupsConfig {
    pub registry: FixupRegistry,            // None | File(path) | Github(owner, repo)
    pub registry_rev: Option<String>,
    pub allow_local_overrides: bool,        // default true
}

pub struct BuckConfig {
    pub file_name: String,                  // default "BUCK"
    pub vendor: bool,                       // default false
}

pub struct PythonVersion(pub u8, pub u8);    // e.g. (3, 12)
```

## 6. Error type machinery

Top-level CLI error type uses `anyhow::Error` (rich context, easy bubbling). Library-internal errors use `thiserror`-derived enums per module (typed for testing). The CLI's `main` converts the final `anyhow::Error` into a `miette::Diagnostic`-style printout (line/column for TOML errors, file paths, suggestions).

S0 implements:

- `ConfigError` enum in `src/error.rs` (variants: `Parse(toml::de::Error)`, `MissingField(&'static str)`, `BadPlatform(String)`, `BadPythonVersion(String)`, `IncompatibleShape`, …)
- `From<ConfigError> for anyhow::Error`
- A small `Diagnostic` trait wrapping `miette` so we can swap printers later without touching error producers.

Error messages must satisfy: every error string names a field or file by path, and (where applicable) a line/column. CI snapshot tests assert this.

## 7. Module layout (S0 slice)

```
src/
├── main.rs               # CLI entrypoint, wires clap → cli/ modules
├── lib.rs                # `pub mod cli; pub mod config; pub mod error;` etc.
├── cli/
│   ├── mod.rs            # CLI struct (clap derive), dispatcher
│   ├── init.rs           # `muntjac init`
│   ├── config_check.rs   # `muntjac config check`
│   ├── debug.rs          # `muntjac debug` (empty group at S0)
│   └── stub.rs           # registers UNIMPLEMENTED verbs (vendor, buckify, audit, …)
├── config.rs             # muntjac.toml parser + Config type
└── error.rs              # error types + diagnostic printer
```

Other modules (`lock/`, `wheel/`, `buck/`, …) are NOT touched in S0. The lib.rs re-exports only what S0 needs.

## 8. Testing

### Unit tests (per module)

- `config.rs`:
  - Parses valid single-tree config.
  - Parses valid multi-tree config.
  - Rejects mixed (`manifest_path` + `[tree.x]`).
  - Rejects missing `[platforms]`.
  - Rejects invalid python version strings (`3`, `3.x`, `3.12.0`).
  - Rejects invalid platform target triples.
  - Rejects unknown registry forms.
  - Round-trips: parse → serialize → parse produces identical Config.

- `cli/init.rs`:
  - Detects existing `pyproject.toml` in CWD.
  - Detects existing `pyproject.toml` in parent dir.
  - Falls back to undetected template when no pyproject found.
  - Refuses to overwrite without `--force`.
  - Respects `[PATH]` argument.

- `error.rs`:
  - TOML parse error includes line/column in the diagnostic.
  - Missing-field error names the field.

### Integration tests (`tests/`)

Cargo integration tests, one binary per concern (`tests/init.rs`, `tests/config_check.rs`, `tests/help.rs`):

- `init`: spawn `muntjac init` in a tempdir, verify expected files exist with expected contents.
- `config_check`: build a known-good config, assert `muntjac config check` exits 0; corrupt one field, assert it exits non-zero with the expected error class.
- `help`: snapshot of `muntjac --help`; locks the verb surface so future stages can't accidentally rename things.

Shared test helpers live in `tests/common/mod.rs` (the standard cargo pattern).

### CI

`.github/workflows/ci.yml`:

```yaml
on: [push, pull_request]
jobs:
  test:
    strategy:
      matrix:
        runner: [ubuntu-latest, ubuntu-24.04-arm, macos-latest]
    runs-on: ${{ matrix.runner }}
    steps:
      - uses: actions/checkout@v4
      - uses: dtolnay/rust-toolchain@stable
      - run: cargo build --locked
      - run: cargo test --locked
      - run: cargo clippy --locked -- -D warnings
      - run: cargo fmt --check
```

No release workflow yet (added in S8).

## 9. Exit criteria

Stage is complete when all of the following are true:

1. `muntjac init` in an empty dir writes `muntjac.toml` + `third-party/python/{BUCK,.gitignore,fixups/.gitkeep}`.
2. `muntjac init` in a dir with `pyproject.toml` detects it and writes the right `manifest_path`.
3. `muntjac init` refuses to overwrite `muntjac.toml` without `--force`.
4. `muntjac --help` lists all phase-1 verbs (`init`, `vendor`, `buckify`, `audit`, `fixups`, `unused`, `config`, `debug`), with non-implemented ones marked.
5. `muntjac --version` prints version + a build identifier.
6. `muntjac config check` validates a good config (exit 0); rejects each of the 7 failure classes listed in §4 with a precise error.
7. `muntjac debug` (with no subcommand) prints `error: debug requires a subcommand`, exit 2.
8. Every stubbed verb prints `not implemented yet (planned for S<n>)`, exit 2.
9. CI matrix (3 platforms) green on `cargo build`, `cargo test`, `cargo clippy -D warnings`, `cargo fmt --check`.
10. All snapshot tests pass; running them twice produces no diff.

## 10. Open questions / risks

- **`miette` integration depth.** miette's full diagnostic ergonomics require source-string annotations. For S0 we use a minimal wrapper (line/col + message); richer source-span rendering deferred to S6/S7 (where the fixup cfg() parser needs them more urgently).
- **Detection ambiguity.** A repo with multiple `pyproject.toml` files (e.g. uv workspace with members) — the upward walk picks the first one found. If that's the wrong choice, user passes `-C <path>` or edits `muntjac.toml`. Documented in the error/output.
- **Defaulting Python versions.** Bumping the default when a new stable Python releases (3.13 → 3.14) requires a muntjac release. Acceptable; init is a one-time write.
- **clap version pin.** clap 4.x has been stable; we pin to `^4.5` to avoid surprise major bumps.
